---
name: Game Insights design direction
description: The user's ongoing visual direction for the Game Insights catalog, quizzes, and result screens.
---

Keep Game Insights clean, concise, visually polished, and consistent with the rest of PLAYR1.

**Why:** the user explicitly asked for the lead magnets to match the app's overall look and feel while making the questions and results easier to use.

Keep the Game Insights catalog to a simple title and four compact quiz blocks; remove extra hero, scouting, and footer content.

**Why:** the user wants the quiz choices to be the focus and has explicitly asked to remove everything else from this page.

Stack all four quiz blocks in one vertical column at every screen size. Match the dashboard training-summary gradient from charcoal at the top to black at the bottom, with white condensed titles and orange icon accents.

**How to apply:** preserve the four quiz topics and their existing routes; keep the page concise and avoid bringing back elaborate scouting graphics or extra copy.

Make all four quiz question screens match PLAYR1 onboarding: a pure black page, compact “Game Insights” heading, uppercase letter-spaced question, and simple orange-outline pill answers with a right chevron. Avoid large containers and extra header copy.

**Why:** the user supplied onboarding screenshots as the exact visual reference and said the previous card-based styling was not close enough.

**How to apply:** use the same shared treatment across all four quizzes; preserve question copy, scoring, branching, results, saving, and back/reset controls.

Use the radar mark for Game Insights in both Hub locations, in matte black with a restrained white glow and monochrome mark. Quiz progress must show both the question count and a thin progress bar; results should present one concise insight, matching drill-library cards, and compact Drill Library / Retake actions.

**Why:** the user provided the desired icon treatment and explicitly asked for visible quiz progress and a simpler insight-to-drill result flow.

**How to apply:** keep result drills connected to real library entries when available, with a clear fallback when a match is unavailable.
