# PLAYR1 Basketball Training Platform

## Overview
PLAYR1 is a "Netflix for basketball drills" platform designed to offer a complete basketball training experience. It provides users with access to professional training videos, enables logging of practice sessions, tracks progress, supports uploading personal training videos, and allows performance benchmarking within a community. The platform's core vision is to foster skill development and community engagement through a rich library of drills, comprehensive progress tracking, user-generated content features, and social functionalities.

## System Architecture
The platform is built using a modern web stack: React with TypeScript for the frontend, an Express.js backend, and a PostgreSQL database managed with Drizzle ORM. Authentication is handled via custom email/password, bcrypt for password hashing, and stateless JWT tokens stored as httpOnly cookies. The UI/UX features Tailwind CSS and shadcn/ui components, adopting an orange primary color scheme and dark mode by default, with mobile accessibility ensured by Capacitor for native iOS and Android apps.

**Key Features:**

*   **Core Training System**: Includes a dynamic drill library, detailed training log with shot location tracking and visual half-court charts, and progress tracking with analytics, shooting heatmaps, and a "Trophy Room" for achievements. The Daily Streak Challenge uses GPT (via Replit AI Integrations / OpenAI) to generate a brand-new, unique drill every day — the same drill for all users globally to create a shared community experience.
*   **User & Community Engagement**: Supports user-generated drills and video uploads, customizable public player profiles, performance comparison, social media sharing, and a public feedback forum for suggestions and bugs.
*   **Role-Based Access**: Features distinct interfaces for players and trainers, including a "Coach / Trainer Mode" for player management, drill assignments, evaluations, and communication.
*   **Communication & Collaboration**: Offers group chat functionalities, a universal connection system with invite capabilities, and integrates push notifications for key events.
*   **Trainer & Session Management**: Trainers can build detailed public profiles, and a full booking flow for training sessions supports scheduling, rescheduling, and group sessions. Google Calendar integration is available for session synchronization.
*   **Player Development Tools**: Trainers can conduct player evaluations with configurable skill attribute ratings. Players can also bulk-import game stats via CSV.
*   **Administrative & Utility**: An Admin Dashboard provides comprehensive management for drills, users, resources, and includes an Analytics Dashboard for platform insights. The Analytics Dashboard is sub-tabbed (Overview / Retention / Funnels / Users / Content / AI Insights / Live). Phase 1 shipped full Overview (KPIs, signups, log activity, role/category breakdowns, top movers WoW) and Retention (D1/D7/D30 curves, weekly cohort heatmap, power-user concentration, composite engagement scoring with at-risk detection). Phase 2 added Funnels — three preset conversion funnels (Activation, Booking, Engagement Loop) over a configurable 7/30/90-day window. Phase 3 added Users (Segmentation) and Content Performance: Users auto-classifies every account into one of 9 behavioral segments (power, daily grinder, weekend warrior, casual, new+active, new+onboarding, at-risk, ghost signup, dormant) with a clickable segment grid that drills into a per-segment user list (capped at 50, sorted deterministically). At-Risk takes priority over Casual so any user with activity in the last 60 days but none in the last 14 is correctly surfaced. Content Performance shows Daily Streak Challenge ROI (7d/28d completions, active streaks, longest streak), category breakdown (drills, 28d logs, unique users, avg logs/drill), top 20 drills, and a "content gaps" table of older drills with no recent logs. Phase 4 shipped Live Activity (real-time dashboard polling every 10s with pause/resume, active-user counts at 1/15/60min, events-per-minute bar chart, recent events feed, top active users, world map of active users) and AI Insights (admin-triggered weekly executive summary via OpenAI gpt-4o, code-based anomaly detection over WoW metric movers with stable metric+direction de-dup, dismissable insight cards). The /generate endpoint enforces 1-per-7-days idempotency to prevent accidental token spend (force=true override available). The world map uses geoip-lite (offline MaxMind DB, no API key, no per-request cost) to derive country/city/lat/lng from each tracked event's request IP — only the derived geo is persisted on `analytics_events.metadata.geo`, the raw IP is never stored. Private/loopback/CGNAT/link-local/multicast addresses are filtered before lookup, and the locations SQL guards against malformed geo data with a regex on lat/lng before casting. The map itself is rendered with react-simple-maps (TopoJSON world atlas) with intensity-scaled dots and a hover label overlay. A lightweight client-side `track()` helper auto-records page views and key events (signup, onboarding completion, drill view, drill log, booking, daily challenge) into `analytics_events` (now indexed by `(event, created_at)` and `(user_id, created_at)`) for funnel/segmentation work. Admins can also manage picklist options like Shot Locations and Shot Types.
*   **Account Management**: Features an onboarding wizard for new users, email notifications for critical events, and an optional parent/guardian visibility feature for minor players.
*   **Monetization**: Integrated Stripe for payment processing, supporting subscriptions and one-time session payments.
*   **Trainer Program Assignment**: Trainers can directly assign their programs to specific connected players from the program editor (`AssignProgramDialog` opened from the editor header). Visibility tier `"connections"` makes a program discoverable to the author's connected players (via `/api/programs/discover/from-trainers`) but hidden from the public catalog (which still filters strictly to `visibility='public'`). Assignment storage method `assignProgramToPlayers(programId, playerIds[], trainerId)` validates each id against the trainer's accepted-connection roster (`getRosterPlayerIds`) and uses a race-safe inline `INSERT … ON CONFLICT DO NOTHING RETURNING` against the partial unique index so the `assigned` vs `alreadyEnrolled` split is accurate even under concurrent calls (no pre-check race). Endpoints: `POST /api/programs/:id/assign` (author-or-admin, validates roster, body `{ playerIds: string[] }` returns `{ assigned, alreadyEnrolled, skipped }`); `GET /api/programs/discover/assigned` (returns active enrollments where `assignedByTrainerId IS NOT NULL` joined with the trainer's user info); `GET /api/programs/discover/from-trainers` (published programs from connected trainers with visibility in `('public','connections')`, excluding programs already enrolled). The `getProgramBySlug` and `enrollUserInProgram` routes also widen access for the `connections` tier when the caller has an accepted connection with the program author. The `playerTrainerConnections` model is symmetric (player_id/trainer_id are lexically sorted user ids, not strict roles), so the helpers treat any accepted counterpart as a roster member — matching the rest of the app's connection semantics. Player-facing UI: `/programs` renders an "Assigned to you" section (trainer photo + "Assigned by" badge) and a "From your trainers" grid above the catalog; the main catalog is deduped against "From your trainers" so a trainer's public program is never rendered twice. The dashboard `ContinueProgramsWidget` shows an "Assigned by {trainer}" subtitle for assigned enrollments. Tracking: existing `program_enroll`/`program_view` events still apply.
*   **Programs (Structured Training)**: Flagship multi-day training programs at `/programs`. Each program is a series of `program_items` grouped by `dayNumber`/`orderInDay` with item types `drill | workout | challenge | watch | rest`. Defaults are user-paced (suggest daily, no enforcement) and players may have multiple concurrent enrollments. Schema lives in `shared/schema.ts` (`programs`, `program_items`, `program_enrollments`, `program_item_completions`; `PROGRAM_VISIBILITY = ["public","unlisted","private","connections"]`); storage methods are in `server/storage.ts` (listPrograms, getProgramBySlug, getActiveEnrollmentsForUser with subquery counts, enrollUserInProgram (idempotent), completeProgramItem (idempotent + recomputes currentDay + program completion)). Player UI: `/programs` (cinematic browse with featured + grid + filters + active-enrollments rail + "Assigned to you" + "From your trainers" sections), `/programs/:slug` (detail page with day-by-day outline + cinematic accent-colored hero + enrollment CTA), `/programs/:slug/today` (the active "today" view with day pager, item cards, complete buttons, pause/resume). The dashboard gets a `ContinueProgramsWidget` above the daily challenge so active programs surface every visit; enrollments with `assignedByTrainerId` show an "Assigned by {trainer}" subtitle. Three system programs are seeded by `server/seed-programs.ts`: `ball-handling-foundation-7` (beginner), `shooters-mindset-30` (intermediate), `finishing-mastery-14` (advanced) — each links to real existing drills with watch days, rest days, and a final challenge. Tracking events: `programs_browse_view`, `program_view`, `program_enroll`, `program_today_view`, `program_item_complete`, `program_abandon`. **Authoring**: Admins author system programs from `/admin` → "Programs" tab; trainers author their own programs from `/trainer/programs`. Both surfaces share `client/src/components/program-list-section.tsx` (list + "New Program" dialog) and the `/programs/:id/edit` editor (`client/src/pages/program-editor.tsx`) which loads via the auth-aware `GET /api/programs/:id/edit` endpoint so admins can edit unpublished/private trainer programs. Authoring routes (`server/routes.ts`): GET `/api/admin/programs` (admin only, all programs), GET `/api/trainer/programs` (caller's authored programs), POST `/api/programs` (admins → `authorType=system`; non-admins forced to `authorType=trainer` + `authorUserId=self`, with `isFeatured` stripped), PATCH `/api/programs/:id` (author/admin; strips `authorType`/`authorUserId`/`isFeatured` for non-admins; slug changes go through `withSlugRetry` which catches PG `23505` and re-derives), DELETE `/api/programs/:id` (409 when enrollments exist — must unpublish), POST/PATCH/DELETE `/api/programs/:id/items` and `/api/programs/items/:itemId`, PATCH `/api/programs/:id/items/reorder` (bulk swap). Storage helpers: `listAllProgramsAdmin`, `listProgramsForAuthor`, `createProgram`, `updateProgram`, `deleteProgram` (deletes items first), `hasProgramEnrollments`, `getProgramItem`, `addProgramItem`, `updateProgramItem`, `deleteProgramItem`, `reorderProgramItems`. Out of scope and pending: the Events wrapper (open/themed event with leaderboard + community wall), program-completion trophies, push reminders for paced programs, cross-day item moves in the editor (only intra-day adjacent swaps via up/down buttons today).
